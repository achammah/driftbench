# Contributing

Merge through a `train/<n>` pull request: `train gate` must be required in branch protection. Ordinary PRs run `pr fast` (cached install, lint, typecheck, build, CLI smoke, and the docs checks) and `pr affected` (tests affected by the diff, reported only); train PRs and main pushes retain the full Node 22/24, Python 3.11/3.12, viewer, replay, leak guard, and validator checks. `pr fast` is the merge-train entry check, takes about three minutes and has a ten-minute timeout; `pr affected` has a 45-minute timeout, is not required and is not an input of `train gate`. The `ci` and `validators` workflows also accept a manual dispatch with a `jobs` input (comma-separated job ids, no spaces). A dispatch runs only the listed jobs, and only on a `train/*` branch; on `main` it runs nothing and `train gate` fails, so a partial run never stands in for the full suite. `train gate` waits for every heavy `ci` job and fails when one failed or was cancelled; a skipped job does not fail it. The `validators` jobs are checked by `train.sh`, which merges a train only when both workflows' runs on its exact head are green.
